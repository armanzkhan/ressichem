Ressichem Procurement System

User Manual — Complete Workflow & How to Use

Version 1.0 · Prepared for Ressichem internal use · July 2026

Purpose. This manual describes the end-to-end procurement workflow in the Ressichem Procurement portal: Local buying, Import buying, and Export documentation — including purchase requisitions, purchase orders, purchase receipts, supplier invoices, payments, PFI, and costing.

2. System overview

The portal is divided into three trade areas:

AreaPurposeMain modules
Local Domestic (Pakistan) purchasing Suppliers, Items, Requisitions, Purchase orders, Purchase receipts, Supplier invoices, Payments, PR Reports, Landed costing
Import Foreign purchasing Same as Local, plus Upload PFI & Document
Export Outbound sales documentation Create PFI, Received PFI, Documents Upload, Shipment Details
Note: Local/Import cover the buy cycle (procure-to-pay). Export is documentation-only and does not use PR / PO / receipts / invoices / payments.

3. Roles & access

Department → approver routing is configured under PR Approvers (admin).

4. Master data (Suppliers & Items)

4.1 Suppliers

  • Create and maintain vendor records before raising POs.
  • Country determines Local vs Import (Pakistan suppliers appear under Local).

4.2 Items

  • Maintain the procurement item catalog.
  • Each item has a trade scope (local / import) used when building PR/PO lines.

5. Local & Import buying cycle (complete)

This is the standard procure-to-pay flow:

PR draft → Submit (submitted) → Approve / Reject / Hold → Create PO (draft) from approved PR → Issue PO (issued) → Purchase receipt (partial or received) → Supplier invoice → Match → Payment (partial or paid) → Optional: Close PO / Landed costing sheet

7. Purchase Order (PO)

Module: Purchase orders

7.1 Create from approved PR

  1. Open an approved PR.
  2. Click Create PO.
  3. Select the supplier (required — PRs do not store supplier).
  4. System creates a draft PO with PR lines and links (prNumber / requisition).

POs can also be created manually, or (Import) converted from a received PFI.

7.2 Issue

From draft, click Issue → status becomes issued. This is the official purchase order.

7.3 Receive

On an issued (or partially received) PO, click Receive:

  • Enter quantity received per line (remaining qty is pre-filled).
  • Post purchase receipt.
  • PO becomes partial if any lines remain open, or received when all quantities are received.

7.4 Close

After receive, use Close to set status closed when the order is complete operationally.

8. Purchase Receipts

Module: Purchase receipts

  • Each receive action posts a purchase receipt document (number like GRN-YYYY-#####).
  • Receipts list shows receipt #, linked PO, supplier, date, lines, and value.
  • Supports full and partial receipts against the same PO over time.

9. Supplier Invoices & matching

Module: Supplier invoices

  1. Create a supplier invoice (optionally link to a PO).
  2. Enter supplier invoice number, date, and total (or inherit PO total).
  3. Click Match to compare invoice total with PO total / received value.
Match resultMeaning
matchedInvoice aligns with PO / received amounts
varianceAmounts differ — review before paying
unmatchedNot yet matched / no PO linked

10. Payments

Module: Payments

  1. Open Payments → add payment.
  2. Select supplier invoice; remaining balance is suggested.
  3. Enter amount, date, method (bank transfer, cheque, cash, LC, other), and reference.
  4. Post payment → invoice becomes partially_paid or paid.

11. Landed costing

Module: Landed costing

  • Separate cost sheet for duties, charges, FX, and landed cost calculations (especially Import).
  • This is not the same as recording a supplier payment.
  • Use after/alongside import purchases for cost analysis and print/export.

12. Import PFI path

Module: Upload PFI & Document

Upload received PFI → Review / accept as ready → Convert to PO (draft) → Issue → Purchase receipt → Invoice → Payment (+ Landed costing as needed)

Import can also skip PFI and use the standard PR → Create PO path.

13. Export workflow

Export is independent of the buy cycle:

Create PFI → Received PFI (as needed) → Documents Upload → Shipment Details

Use Export for outbound commercial documents and shipment tracking — not for purchasing stock.

16. End-to-end examples

16.1 Local purchase

  1. Requester creates & submits PR (Local).
  2. Department approver approves.
  3. Buyer clicks Create PO, selects Pakistan supplier, issues PO.
  4. On delivery, buyer Receives (full or partial) → purchase receipt posted.
  5. Buyer records Supplier invoice, runs Match.
  6. Accounts/buyer posts Payment until invoice is paid.
  7. Optionally Close the PO.

16.2 Import purchase via PFI

  1. Upload received PFI under Import.
  2. Convert PFI to draft PO → Issue.
  3. Receive shipments (partial OK) → invoices → match → payments.
  4. Maintain landed costing sheet for duties/charges/FX.

16.3 Export

  1. Create export PFI.
  2. Upload documents and maintain shipment details as goods leave.
